# Stage 03: Diff parsing and mechanical proofs

**Status:** In progress (on main; CI not yet confirmed)
**Depends on:** 02
**Unblocks:** 10
**Owns:** `src/domain/diff/` except `types.ts` (stage 02), `formatting.ts` and `call-graph.ts` (stage 04)

## Goal

Turn a raw unified diff into `FileChange[]` with stable hunk IDs, and prove which hunks are mechanical using checks that need no parser: generated files, whitespace, pure renames and moved code.

This is the most safety-critical code in the product. A false "mechanical" hides code from the reviewer (ENGINEERING.md §6, §7). Every rule below errs toward **not** proving.

## Tasks

### 1. Unified diff parser: `parse-diff.ts`

`parseUnifiedDiff(diff: string): Result<FileChange[], DiffParseError>` where `DiffParseError = { line: number; message: string }`.

Must handle git-style diffs as produced by GitHub and Bitbucket:

| Input | Handling |
|---|---|
| `diff --git a/x b/y` | Starts a file. |
| `new file mode`, `deleted file mode` | Status `added` / `deleted`. |
| `old mode` / `new mode` | Set `oldMode`/`newMode`. With no hunks: status `modified`, not mechanical, because a mode change (e.g. made executable) can matter. |
| `similarity index`, `rename from`, `rename to` | Status `renamed`, `oldPath` set. May have hunks. |
| `copy from`, `copy to` | Treat as `added` at the new path. |
| `Binary files … differ`, `GIT binary patch` | `binary: true`, no hunks. |
| `--- a/x`, `+++ b/x`, `/dev/null` | Paths and add/delete detection. |
| Quoted paths (`"a/with space\tand \303\251"`) | Unquote C-style escapes, including octal UTF-8 bytes. |
| `@@ -a,b +c,d @@ heading` | Hunk. Missing counts mean 1. `heading` becomes `sectionHeading`. |
| `\ No newline at end of file` | Not a line. Set `noNewlineAtEnd` on the preceding line so a newline-only change can be recognized. |
| CRLF inside content | Keep `\r` in `text` so line-ending changes are visible to the whitespace check. |
| Empty diff | `ok([])`. |

- Compute `oldLine`/`newLine` for every line, and `additions`/`deletions` per file.
- Line counts in the hunk header must match the lines read; a mismatch is a `DiffParseError`, never a silent fix.

### 2. Hunk IDs: `hunk-id.ts`

`hunkId(path, hunk)`: `"h_"` + FNV-1a 64-bit hex (from `src/domain/shared/hash.ts`) of

```
{path}\n{oldStart},{oldLines},{newStart},{newLines}\n{each line as kind-char + text, joined by \n}
```

The same diff always gives the same IDs. If two hunks in one PR collide, append `-2`, `-3`, … in file order. Assign IDs inside `parseUnifiedDiff`.

### 3. Mechanical proofs: `proofs.ts`

```ts
findMechanicalProofs(files: FileChange[], context: ProofContext): MechanicalProof[]
interface ProofContext {
  gitattributes: string | null;            // the BASE version; stage 10 passes base even if the PR edits it
  baseContents: ReadonlyMap<string, string | null>;   // by path (oldPath for renames)
  headContents: ReadonlyMap<string, string | null>;
}
```

At most one proof per hunk. If several apply, keep the first in this order: generated, rename, move, whitespace.

#### Generated

A hunk is generated if its file is any of:

- **A lockfile** by basename: `package-lock.json`, `npm-shrinkwrap.json`, `pnpm-lock.yaml`, `yarn.lock`, `bun.lock`, `Cargo.lock`, `go.sum`, `poetry.lock`, `uv.lock`, `Pipfile.lock`, `Gemfile.lock`, `composer.lock`, `Podfile.lock`, `packages.lock.json`, `gradle.lockfile`, `flake.lock`, `mix.lock`, `pubspec.lock`.
- **Marked in `.gitattributes`** with `linguist-generated` or `linguist-vendored` (set or `=true`). Implement the subset of gitattributes matching we need: `*`, `**`, `?`, leading `/` anchors, trailing `/` for directories, later lines override earlier ones, `-attr` and `attr=false` unset. Always use the **base** version, so a PR can't hide code by editing `.gitattributes`.
- **Has a generated marker in the first 5 lines of both the base and the head version**: `@generated`, `Code generated … DO NOT EDIT.`, `<auto-generated`. A marker that appears only in the head version doesn't count: otherwise adding a marker would hide the file.

`detail` names the reason, e.g. `lockfile (pnpm-lock.yaml)`, `.gitattributes: linguist-generated`, `marker "@generated" in base and head`.

#### Rename

A file with status `renamed` and no hunks gets one file-level proof (`path` set, `hunkId: null`) with detail `renamed from {oldPath}, content unchanged`.

#### Whitespace

A hunk is whitespace-only if, after removing blank lines, its deleted and added lines are equal once **trailing whitespace and `\r`** are stripped. A hunk that only adds or removes blank lines also qualifies.

Indentation and inner whitespace are **not** normalized here: they can change meaning (Python, YAML, string literals). Stage 04 proves those with a parser.

#### Move

A hunk is moved if **every** added and deleted line in it belongs to a moved region:

- A moved region is a run of at least **3 non-blank** consecutive deleted lines that appears as consecutive added lines somewhere else in the PR (another hunk or file), or the reverse.
- Lines are compared after stripping trailing whitespace. Leading indentation may also be stripped **only** if the file's extension is in an explicit whitespace-insensitive list (`.ts`, `.tsx`, `.js`, `.jsx`, `.mjs`, `.cjs`, `.java`, `.kt`, `.go`, `.rs`, `.c`, `.h`, `.cpp`, `.hpp`, `.cs`, `.swift`, `.php`, `.rb`, `.scala`, `.css`, `.scss`, `.json`, `.sql`). Unknown extensions are treated as whitespace-sensitive.
- Each region can be matched once.
- A hunk with any changed line outside a matched region gets no proof.

`detail` says where the code went or came from, e.g. `moved to src/b.ts:40–72, identical`.

### 4. Lockfile warnings: `warnings.ts`

`lockfileWarnings(files): string[]`. If a lockfile changes but no manifest in the same directory changes (`package.json`, `Cargo.toml`, `go.mod`, `pyproject.toml`, `Pipfile`, `Gemfile`, `composer.json`, `Podfile`, `pubspec.yaml`, `mix.exs`, `flake.nix`, `build.gradle`, `build.gradle.kts`), return a warning such as `pnpm-lock.yaml changed without a change to package.json`. The lockfile stays collapsed, but the reviewer sees the warning at the top of the review.

### 5. Exports

`src/domain/diff/index.ts` exports `parseUnifiedDiff`, `hunkId`, `findMechanicalProofs`, `lockfileWarnings` and the types. Stage 04 appends its exports to the same file.

## Tests

**Parser**, from real `git diff` output committed as `.diff` fixtures. Add `scripts/make-diff-fixtures.sh`, which builds a temp repo, makes each change and writes the diff, so fixtures can be regenerated:

- added, deleted, modified, renamed, renamed and modified, copied, binary, mode-only, empty file added
- missing newline at end of file (each side), CRLF content, quoted path with spaces and non-ASCII
- multiple hunks, hunk header without counts, section headings, a 2,000-line hunk
- malformed input: header counts that don't match, garbage between files

**Hunk IDs:** stable across runs, differ when any input part differs, collision suffixes.

**Proofs, including adversarial cases that must NOT be proved:**

| Case | Expected |
|---|---|
| Trailing-whitespace change plus a changed character inside a string on the same line | No proof |
| Python file re-indented | No whitespace proof (stage 04 decides) |
| Moved block with one character changed | No move proof |
| Moved block with one extra line inserted | No proof for the hunk with the extra line |
| "Moved" block of 2 lines, or of only `}` lines | No move proof |
| `@generated` added to a file in this PR | No generated proof |
| `.gitattributes` edited in this PR to mark a file generated | No generated proof (base version used) |
| File named `package-lock.json.bak` | Not a lockfile |
| Lockfile changed without manifest change | Proof plus a warning |

And positive cases for each proof kind, including a function moved between two files and a moved block in a whitespace-insensitive language with changed indentation.

## Definition of done

- [x] Parser handles every input in the table, tested with real git output.
- [x] Every adversarial case above has a test and is not proved.
- [x] Coverage thresholds pass (this is domain code: 90% branches).
- [x] `scripts/make-diff-fixtures.sh` regenerates the fixtures.

## Open issues

- **Moves within one file can reorder statements.** A block moved between two hunks of the same file gets a move proof, as this doc asks, but moving lines inside a long function changes the order they run in. Stage 04 could require a moved region to be whole top-level declarations.
- **Indentation-insensitive moves ignore indentation inside multi-line strings** (template literals, raw strings), which does change the string. The detail says "identical apart from indentation", but the hunk is still collapsed.
- **Only the root `.gitattributes` is read.** A nested one that unsets `linguist-generated` is ignored, so such a file could be proved generated when git wouldn't mark it.

## Notes for later stages

Where the code differs from or adds to this doc:

- **Stricter than the doc, so fewer proofs:**
  - A moved region needs 3 lines with a letter or digit, not just 3 non-blank lines, so `}` and `);` don't count towards the minimum. Blank lines are ignored inside and around moved blocks, as the whitespace proof ignores them.
  - A move must be between two different hunks. Moves into or out of a generated file aren't proved, since both ends would be hidden.
  - No proof at all for a file whose mode changed, even with hunks, because collapsing it would hide the mode change.
  - A renamed file is generated only if both its old and new path are (both lockfile names, or both marked in `.gitattributes`), so renaming code to `yarn.lock` doesn't hide it. A rename proof needs a non-binary file.
  - A marker must be the same marker in base and head. Contents missing from `baseContents`/`headContents` count as no marker.
  - The whitespace check compares each run of changed lines between context lines on its own, so a line moved past a context line isn't whitespace-only. "Trailing whitespace" means spaces, tabs and `\r`; a non-breaking space is not whitespace.
- **`.gitattributes` follows git, not this doc, for trailing slashes.** `gen/ linguist-generated` matches nothing, because git doesn't apply a pattern that matches a directory to the files inside (checked with `git check-attr`); write `gen/**`. Character classes are supported. A pattern it can't read unsets its attributes for every path instead of being skipped. `linguist-generated=<anything but true>` counts as unset.
- **Lockfile warnings** accept a matching manifest in the same directory *or below*, because workspaces (pnpm, yarn, Cargo, uv) keep one lockfile at the root. `pnpm-workspace.yaml` counts for `pnpm-lock.yaml`, and `packages.lock.json` (NuGet) pairs with `*.csproj`, `*.fsproj` and `*.vbproj`. The warning names every matching manifest, e.g. `pnpm-lock.yaml changed without a change to package.json or pnpm-workspace.yaml`.
- **Move details** list every region, joined with `; `, e.g. `moved to src/b.ts:10–12, identical; moved to src/c.ts:10–12, identical`. "Moved from" names the old path for a renamed file. Whitespace details say what changed: `whitespace only: blank lines, trailing whitespace`, or `line endings`, or `newline at end of file`.
- **Parser.** Paths come from `rename`/`copy` lines, then `---`/`+++`, then `diff --git`. Git appends a tab to `---`/`+++` paths that contain a space, which the parser drops. A hunk before the `---`/`+++` lines, an empty line inside a hunk, or any unknown header line is an error. `DiffParseError.line` is 1-based. Stage 10: small-feature's diff parses to exactly `smallFeatureFiles` with `language: null`, and refactor-move gets a proof for every hunk except `src/config.ts` (the reformat, stage 04's).
- **Copies** (only with `git diff -C`) are added files with no hunks when identical, so the reviewer sees an empty added file. GitHub's and Bitbucket's diffs don't detect copies, so this shouldn't come up.
- **Outside this stage's paths:** `web/tsconfig.json` (stage 13's) excludes `src/domain/**/*.test.ts`, because domain tests read fixtures with `node:fs` and the web program has no Node types; the root tsconfig still typechecks them. `vitest.config.ts` (stage 01's) measures coverage of `.ts`/`.tsx` files only, so `.diff` fixtures aren't parsed as source.
